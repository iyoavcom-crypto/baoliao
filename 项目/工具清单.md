# 工具清单

本文档列出项目中 `src/tools` 目录下的所有工具模块及其功能说明。

```
src/tools/
├── crypto/          # 加密工具模块
```

## 1. Crypto 工具模块

**路径**: `src/tools/crypto/`

**版本**: since 1.3.2 (2025-10-19)

**作者**: Z-kali

### 1.1 功能概述

提供 AES-256-GCM 加/解密、口令 `scrypt` 哈希校验、PIN 加/解密、密钥提供器，以及 HTTP 交互用的类型模式。

### 1.2 设计原则

- 安全默认
- 常量时间比较
- 明确的环境配置
- 可扩展的密钥管理

### 1.3 核心组件

#### 1.3.1 密码哈希 (`password.ts`)

- `hashPassword(password: string): Promise<string>` — 生成 `scrypt` 哈希
- `verifyPassword(password: string, stored: string): Promise<boolean>` — 校验哈希
- `verifyPasswordUpgrade(password: string, stored: string): Promise<{ ok: boolean; needsRehash: boolean; newHash?: string }>` — 校验并按当前基线评估是否重算

**参数基线**: `SCRYPT={N:32768, r:8, p:1, keylen:32}`

#### 1.3.2 AES-GCM 加密 (`aesgcm.ts`)

- `encrypt(plain: Buffer, key: SymmetricKey, aad?: Buffer): AesGcmPayload` — AES-256-GCM 加密
- `decrypt(payload: AesGcmPayload, key: SymmetricKey): Buffer` — AES-256-GCM 解密
- `safeKidEqual(a: string, b: string): boolean` — KID 常量时间比较

**特性**:
- 随机 IV（12 字节）
- 16 字节 Tag
- 可选 AAD（附加认证数据）

#### 1.3.3 PIN 加密 (`pin.ts`)

- `deriveKeyFromSecret(secret: string, kid = "env:PIN_SECRET"): SymmetricKey` — 由 `secret` 派生 32B 密钥
- `encryptPin(pin: string, secret: string): Promise<string>` — 加密并返回序列化 JSON
- `decryptPin(payloadJson: string, secret: string): Promise<string>` — 解密 PIN

#### 1.3.4 密钥管理 (`kms.ts`)

- `interface KeyProvider` — 密钥提供器接口
- `class EnvKeyProvider implements KeyProvider` — 读取主密钥与轮换配置
  - `getActiveKey(): Promise<SymmetricKey>` — 获取当前激活密钥
  - `getKeyById(kid: string): Promise<SymmetricKey|null>` — 按 KID 获取历史密钥
  - `rotateIfNeeded(): Promise<void>` — 轮换占位

#### 1.3.5 环境配置 (`crypto-env/`)

- `loadCryptoEnv(): Readonly<CrypEnv>` — 读取并校验环境配置
- `cryptoEnv` — 冻结的配置实例（模块加载时计算）

#### 1.3.6 类型模式 (`schemas/`)

提供 HTTP 层入参/出参 TypeScript 接口：
- `THashReq/THashRes` — 口令哈希接口
- `TVerifyReq/TVerifyRes` — 口令校验与升级提示
- `TEncryptReq/TEncryptRes` — AES-GCM 加密请求与响应
- `TDecryptReq/TDecryptRes` — AES-GCM 解密请求与响应

### 1.4 环境变量配置

| 变量名 | 用途 | 约束 |
|--------|------|------|
| `PASSWORD_PEPPER` | 增强 `scrypt` 安全性 | 长度 ≥16 字符 |
| `DATA_MASTER_KEY` | 对称加密主密钥 | 32 字节 `base64url` |
| `DATA_MASTER_KEY_KID` | 主密钥 KID | 可选 |
| `KEY_ROTATION_DAYS` | 密钥轮换提示间隔 | 可选，默认 90 |
| `PIN_SECRET` | PIN 加/解密的密钥来源 | 长度 ≥16 字符 |

### 1.5 最佳实践

- 使用 `AAD` 绑定业务上下文（如订单号与受众），避免明文被跨上下文复用
- KID 比较使用 `safeKidEqual`，避免侧信道信息泄漏
- 为旧哈希提供平滑升级：使用 `verifyPasswordUpgrade` 返回 `newHash` 并在用户登录成功后更新
- 切勿记录或输出密钥与明文敏感信息
- 生产环境实现真实的密钥轮换与持久化存档

## 2. JWT 工具模块

**路径**: `src/tools/jwt/`

**版本**: since 1.0.0 (2025-09-14)

**作者**: Z-kali

### 2.1 功能概述

面向 Node 22（ESM，TypeScript）的 JWT 模块集合：服务类、密钥提供器工厂、守卫与错误模型，以及常用工具函数。统一采用"异步函数以 Async 结尾"的命名规范。

### 2.2 核心组件

#### 2.2.1 JWT 服务 (`service.ts`)

**JwtService 类**：
- `signAsync(kind: TokenKind, payload: JwtUserPayload): Promise<string>` — JWT 签发
- `verifyAsync(token: string): Promise<JwtUserPayload>` — JWT 验证
- `rotateRefreshAsync(refreshToken: string, mutate?: (p: JwtUserPayload) => JwtUserPayload): Promise<{ access: string; refresh: string; payload: JwtUserPayload }>` — 刷新令牌轮转

#### 2.2.2 密钥工厂 (`keys/`)

- `createHSKeyProvider(options: HSKeyOptions): KeyProvider` — HS256 对称密钥
- `createRSKeyProvider(options: RSKeyOptions): KeyProvider` — RS256 非对称密钥
- `createKeyProvider(options: KeyFactoryOptions): KeyProvider` — 统一工厂（HS/RS）

**HS 选项**: `secret? | secretEnv? | secretPath? | kid?`

**RS 选项**: `privateKeyPath? | publicKeyPath? | privateKeyEnv? | publicKeyEnv? | kid?`

#### 2.2.3 守卫函数 (`guards/`)

所有守卫函数通过命名空间 `Guards` 导出：
- `assertAppId` — 应用 ID 断言
- `assertUserId` — 用户 ID 断言
- `assertUserCode` — 用户代码断言
- `assertRole` — 角色断言
- `assertTeam` — 团队断言
- `assertTokenKind` — 令牌类型断言
- `assertScopes` — 作用域断言
- `assertVip` — VIP 用户断言
- `assertDevice` — 设备绑定断言

#### 2.2.4 错误处理 (`errors/`)

- `AuthError` — 认证错误类
- `AuthErrorCode` — 错误码枚举
- `AuthProblem` — 错误问题描述接口

#### 2.2.5 工具函数 (`utils.ts`)

- `ttlToSeconds` — TTL 转换为秒数
- `nowSec` — 获取当前时间戳（秒）
- `nanoid` — 生成唯一 ID
- `shortId` — 生成短 ID

#### 2.2.6 环境配置 (`jwt-env/`)

- `jwtEnv` — 加载并冻结的 JWT 环境配置
- `JwtEnv` — JWT 环境配置类型定义

### 2.3 令牌类型

```typescript
enum TokenKind {
  Access = "access",
  Refresh = "refresh"
}
```

### 2.4 安全配置

```typescript
interface SecurityConfig {
  algorithm: "HS256" | "RS256";      // JWT签名算法
  accessTokenTTL: string;            // 访问令牌TTL
  refreshTokenTTL: string;           // 刷新令牌TTL
  enableDeviceBinding: boolean;      // 是否启用设备绑定
  enableRedisBlacklist: boolean;     // 是否启用Redis黑名单
}
```

### 2.5 TTL 格式支持

- `s`: 秒 (例: `30s`)
- `m`: 分钟 (例: `15m`)
- `h`: 小时 (例: `2h`)
- `d`: 天 (例: `7d`)

### 2.6 环境变量配置

| 变量名 | 用途 | 示例值 |
|--------|------|--------|
| `JWT_ALGORITHM` | JWT 签名算法 | `HS256` 或 `RS256` |
| `JWT_ACCESS_TTL` | 访问令牌有效期 | `15m` |
| `JWT_REFRESH_TTL` | 刷新令牌有效期 | `7d` |
| `JWT_SECRET` | HS256 密钥 | 仅 HS256 使用 |
| `JWT_PRIVATE_KEY_PATH` | RS256 私钥路径 | 仅 RS256 使用 |
| `JWT_PUBLIC_KEY_PATH` | RS256 公钥路径 | 仅 RS256 使用 |

### 2.7 快速创建服务

`createJwtServiceFromEnv(): JwtService` — 根据环境变量快速创建 JWT 服务实例

### 2.8 命名规范变更说明

**服务类方法**:
- `sign` → `signAsync`
- `verify` → `verifyAsync`
- `rotateRefresh` → `rotateRefreshAsync`

**密钥提供器接口方法**:
- `getActiveKey` → `getActiveKeyAsync`
- `getVerifyKey` → `getVerifyKeyAsync`
- `getKeyId` → `getKeyIdAsync`

## 3. Logging 工具模块

**路径**: `src/tools/logging/`

**版本**: since 1.0.0 (2025-11-25)

**作者**: Z-kali

### 3.1 功能概述

提供基础日志记录接口与简单实现，支持多日志级别、结构化输出与控制台彩色输出。

### 3.2 日志级别

```typescript
type LogLevel = "trace" | "debug" | "info" | "warn" | "error" | "fatal"
```

**级别数值映射**:
- `trace`: 10 — 最详细，仅调试用途
- `debug`: 20 — 开发调试信息
- `info`: 30 — 常规业务信息
- `warn`: 40 — 潜在问题或异常情况
- `error`: 50 — 业务错误或可恢复异常
- `fatal`: 60 — 严重错误，通常影响进程存活

### 3.3 核心接口

#### 3.3.1 Logger 接口

```typescript
interface Logger {
  getLevel(): LogLevel;
  setLevel(level: LogLevel): void;
  child(name: string, base?: Record<string, unknown>): Logger;
  trace(msg: string, ctx?: Record<string, unknown>): void;
  debug(msg: string, ctx?: Record<string, unknown>): void;
  info(msg: string, ctx?: Record<string, unknown>): void;
  warn(msg: string, ctx?: Record<string, unknown>): void;
  error(msg: string, ctx?: Record<string, unknown>): void;
  fatal(msg: string, ctx?: Record<string, unknown>): void;
  log(level: LogLevel, msg: string, ctx?: Record<string, unknown>, err?: unknown): void;
}
```

#### 3.3.2 LogEvent 结构

```typescript
interface LogEvent {
  ts: string;                        // 日志时间戳（ISO 8601）
  level: LogLevel;                   // 日志级别
  name?: string;                     // 日志记录器名称
  msg: string;                       // 日志消息
  ctx?: Record<string, unknown>;     // 结构化上下文字段
  err?: SerializedError;             // 关联的错误信息
  traceId?: string;                  // 追踪 ID
}
```

### 3.4 核心函数

#### 3.4.1 日志记录器管理

- `createLogger(options?: LoggerOptions): Logger` — 创建新的独立日志记录器实例
- `getLogger(name?: string): Logger` — 获取全局根记录器或其子记录器
- `setGlobalLogLevel(level: LogLevel): void` — 设置全局根记录器的日志级别
- `getGlobalLogLevel(): LogLevel` — 获取全局根记录器当前日志级别

#### 3.4.2 便捷函数

- `logError(error: unknown, message?: string, ctx?: Record<string, unknown>): void` — 使用全局记录器记录错误日志

#### 3.4.3 上下文追踪

- `runWithTraceId(traceId: string, fn: () => void): void` — 在指定的 traceId 上下文中执行函数
- `runWithRequestContext<T>(ctx: LogContext, fn: () => T): T` — 在指定的请求上下文中执行函数

#### 3.4.4 专用日志记录器

- `createConnectionLogger(name: string)` — 创建连接日志记录器
  - `attempt(ctx?)` — 记录连接尝试
  - `success(ctx?)` — 记录连接成功
  - `failure(error, ctx?)` — 记录连接失败
  - `closed(reason?, ctx?)` — 记录连接关闭

- `logHttpAccess(ctx)` — 记录 HTTP 访问日志

### 3.5 配置选项

```typescript
interface LoggerOptions {
  name?: string;                     // 记录器名称
  level?: LogLevel;                  // 日志输出的最小级别
  pretty?: boolean;                  // 是否使用人类可读格式输出
  base?: Record<string, unknown>;    // 所有日志事件的基础上下文字段
}
```

### 3.6 环境变量

| 变量名 | 用途 | 默认值 |
|--------|------|--------|
| `LOG_LEVEL` | 设置日志级别 | production: `info`, development: `debug` |
| `LOG_PRETTY` | 启用彩色输出 | development: `true` |
| `NODE_ENV` | 运行环境 | - |

### 3.7 输出格式

#### JSON 格式（生产环境）
```json
{"ts":"2025-12-30T12:00:00.000Z","level":"info","name":"app","msg":"服务启动","ctx":{"port":3000}}
```

#### Pretty 格式（开发环境）
```
2025-12-30T12:00:00.000Z [INFO] app 服务启动 {"port":3000}
```

### 3.8 特性

- 支持 AsyncLocalStorage 实现的异步上下文追踪
- 自动序列化错误对象（包括 stack、cause、code）
- 彩色控制台输出（支持 ANSI 颜色码）
- 结构化日志记录
- 子记录器继承与上下文合并

## 4. Secrets 工具模块

**路径**: `src/tools/secrets/`

**版本**: since 1.0.0 (2025-09-12)

**作者**: Z-kali

### 4.1 功能概述

安全密钥生成与格式化输出工具脚本，用于生成项目所需的各类密钥。

### 4.2 核心函数

#### 4.2.1 密钥生成

- `generatePinSecret(length = 32): string` — 生成 PIN 密钥（base64url 编码）
- `generatePasswordSecret(length = 32): string` — 生成密码加密密钥（base64url 编码）
- `generateJwtSecret(length = 32): string` — 生成 JWT 签名密钥（base64url 编码）

#### 4.2.2 格式化输出

- `formatOutput(pin: string, pwd: string, jwt?: string, format: SecretFormat = "env"): string` — 格式化输出密钥字符串

**支持的输出格式**:
- `env` — 环境变量格式
- `json` — JSON 格式

### 4.3 CLI 使用

作为脚本执行时，支持以下环境变量：

| 变量名 | 用途 | 默认值 |
|--------|------|--------|
| `LENGTH` | 随机字节长度 | `32` |
| `LENGTH_MODE` | 长度模式 (`bytes` 或 `encoded`) | `encoded` |
| `FORMAT` | 输出格式 (`env` 或 `json`) | `env` |

**示例**:
```bash
# 生成默认长度的密钥（env 格式）
node src/tools/secrets/index.ts

# 生成 64 字节的密钥（JSON 格式）
LENGTH=64 LENGTH_MODE=bytes FORMAT=json node src/tools/secrets/index.ts
```

### 4.4 输出示例

#### ENV 格式
```
PIN_SECRET=abc123...
PASSWORD_SECRET=def456...
JWT_SECRET=ghi789...
```

#### JSON 格式
```json
{
  "PIN_SECRET": "abc123...",
  "PASSWORD_SECRET": "def456...",
  "JWT_SECRET": "ghi789..."
}
```

## 6. 使用建议

### 6.1 安全性

1. **密钥管理**
   - 使用环境变量存储敏感密钥
   - 生产环境必须使用强随机密钥
   - 定期轮换密钥
   - 使用 `secrets` 模块生成密钥

2. **加密最佳实践**
   - 使用 AAD（附加认证数据）绑定业务上下文
   - 避免在日志中输出明文敏感信息
   - 使用常量时间比较防止侧信道攻击

3. **密码处理**
   - 使用 `PASSWORD_PEPPER` 增强安全性
   - 支持密码哈希参数升级机制
   - 永不存储明文密码

### 6.2 认证授权

1. **JWT 策略**
   - 根据业务需求选择 HS256 或 RS256
   - 合理设置 Access Token 和 Refresh Token 的有效期
   - 使用刷新令牌轮转机制
   - 根据需要启用设备绑定和黑名单

2. **守卫使用**
   - 在路由或中间件中使用 Guards 进行权限检查
   - 捕获 `AuthError` 进行统一错误处理

### 6.3 日志记录

1. **日志级别选择**
   - 开发环境使用 `debug` 或 `trace`
   - 生产环境使用 `info` 或 `warn`
   - 关键错误使用 `error` 或 `fatal`

2. **结构化日志**
   - 使用 `ctx` 参数传递结构化上下文
   - 使用 `traceId` 追踪请求链路
   - 使用子记录器区分不同模块

3. **性能考虑**
   - 避免在高频路径记录过多日志
   - 生产环境禁用 `trace` 和 `debug` 级别

### 6.4 环境配置

所有工具模块都依赖环境变量配置，建议：
- 使用 `.env` 文件管理开发环境配置
- 使用密钥管理服务（KMS）管理生产环境密钥
- 严格区分开发、测试、生产环境的配置
- 定期审计环境变量配置
